# BWC 영업 대시보드

BWC 영업본부의 주간·월간 실적을 분리해 보는 정적 웹 대시보드입니다. 별도 서버나 데이터베이스 없이 GitHub Pages에 올릴 수 있습니다.

## 핵심 구성

- 로그인 비밀번호: `bwc1561`
- 주간보고: DRUM/EA 수량, 매출, 계획 달성률, 전년 동기비, 누계 매출
- 월간보고: DRUM/EA 수량, 매출, 매출이익, 영업이익, 매출이익률, 영업이익률
- 조직 필터: 동부·중부·서부 본부 → 부산·울산·포항·광주·천안·충주·수원·인천 영업소
- 유종별 이익률: `data.json`의 `product` 값으로 자동 집계
- 미수 관련 시트와 지표: 변환 및 화면에서 모두 제외

현재 예시 데이터는 업로드된 주간/월간 Excel을 기준으로 작성했습니다. 월간 원본에는 유종 또는 제품군 열이 없으므로 `product`가 `유종 미분류`로 저장되어 있습니다. 실제 유종별 분석을 하려면 아래의 “유종 데이터 넣기”를 적용하세요.

## 파일 구성

```text
index.html   화면 구조와 로그인/업데이트 창
styles.css   화면 디자인과 반응형 레이아웃
script.js    필터, 집계, 차트, Excel 변환 로직
data.json    대시보드 데이터
README.md    설치와 업데이트 안내
```

## GitHub Pages에 올리기

1. 위 5개 파일을 GitHub 저장소의 같은 폴더에 올립니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Deploy from a branch**를 선택하고, 배포할 브랜치와 `/ (root)`를 지정합니다.
4. 안내된 GitHub Pages 주소로 접속합니다.
5. 비밀번호 `bwc1561`을 입력합니다.

`data.json`을 읽기 위해 웹 서버가 필요합니다. 컴퓨터에서 `index.html`을 직접 더블클릭하면 브라우저 보안 정책 때문에 데이터가 표시되지 않을 수 있습니다.

로컬 확인 예시:

```bash
python -m http.server 8000
```

그다음 브라우저에서 `http://localhost:8000`을 엽니다.

## 가장 쉬운 데이터 업데이트 방법

대시보드 오른쪽 위의 **Excel 업데이트** 버튼을 사용합니다.

1. 주간 갱신 시 `※ 작성방법_주 마감.xlsx` 형식의 파일을 선택합니다.
2. 월간 갱신 시 `※ 작성방법_마감자료.xlsx` 형식의 파일을 선택합니다.
3. **변환 및 미리보기**를 누릅니다.
4. 화면의 수치와 영업소 구성을 확인합니다.
5. **data.json 다운로드**를 누릅니다.
6. GitHub 저장소의 기존 `data.json`을 내려받은 파일로 교체합니다.

주간과 월간 중 하나만 선택해도 됩니다. 선택하지 않은 보고서 데이터는 기존 값이 유지됩니다.

### Excel에서 읽는 시트

| 구분 | 시트 | 사용 항목 |
|---|---|---|
| 주간 | `주 마감` | 본부, 영업소, 코드, 포장단위, 계획/실적/전년 수량, 계획/실적/전년 매출, 누계 |
| 월간 | `거래형태별 이익` | 본부, 영업소, 포장단위, 실적수량, 실적금액, 실적매출이익, 실적영업이익 |
| 월간 기간 판정 | `BWC` | 월별 실적이 마지막으로 입력된 월 |

다음 시트는 읽지 않습니다: `영업소_미수`, `미수현황`. 따라서 미수 데이터가 대시보드에 포함되지 않습니다.

## 유종 데이터 넣기

현재 제공된 월간 Excel에는 유종/제품군을 구분하는 열이 없습니다. 다음 중 한 가지 방법을 사용하세요.

### 방법 1. Excel에 유종 열 추가

`거래형태별 이익` 시트의 두 번째 헤더 행에 `유종`, `제품군`, 또는 `품목군`이라는 열을 추가하고 각 실적 행에 값을 채웁니다. 기존 실적 열 이름은 유지해야 합니다. 대시보드의 Excel 변환 기능이 해당 열을 찾아 `product`로 저장합니다.

예시 값:

```text
유압유
절삭유
방청유
그리스
기타
```

### 방법 2. data.json 직접 수정

월간 `records`에서 `product` 값을 실제 유종으로 바꿉니다. 같은 영업소에 여러 유종이 있으면 레코드를 복제한 뒤 각 유종의 수량·매출·이익을 나누어 입력합니다.

```json
{
  "division": "동부",
  "office": "부산",
  "officeCode": "A1210",
  "product": "유압유",
  "quantityDrum": 1200.5,
  "quantityEa": 320,
  "revenue": 850000000,
  "grossProfit": 180000000,
  "operatingProfit": 92000000
}
```

이익률은 입력하지 않습니다. 화면에서 다음과 같이 계산합니다.

- 매출이익률 = 매출이익 ÷ 매출
- 영업이익률 = 영업이익 ÷ 매출

## data.json 구조

```json
{
  "meta": {},
  "organization": [],
  "weekly": [
    { "period": "2026-W34", "asOf": "2026-08-21", "records": [] }
  ],
  "monthly": [
    { "period": "2026-07", "records": [] }
  ],
  "monthlyTrend": []
}
```

### 주간 레코드 필수 필드

| 필드 | 의미 |
|---|---|
| `division`, `office`, `officeCode` | 본부, 영업소, 영업소 코드 |
| `packageUnit` | `DRUM` 또는 `EA` |
| `planQuantity`, `quantity`, `priorQuantity` | 주간 계획·실적·전년 수량 |
| `planRevenue`, `revenue`, `priorRevenue` | 주간 계획·실적·전년 매출(원) |
| `ytdPlanQuantity`, `ytdQuantity`, `ytdPriorQuantity` | 누계 수량 |
| `ytdPlanRevenue`, `ytdRevenue`, `ytdPriorRevenue` | 누계 매출(원) |

### 월간 레코드 필수 필드

| 필드 | 의미 |
|---|---|
| `division`, `office`, `officeCode` | 본부, 영업소, 영업소 코드 |
| `product` | 유종 또는 제품군 |
| `quantityDrum`, `quantityEa` | 단위별 판매수량 |
| `revenue` | 매출(원) |
| `grossProfit` | 매출이익(원) |
| `operatingProfit` | 영업이익(원) |

숫자는 쉼표나 `원` 문자가 없는 JSON 숫자로 저장합니다. `0`은 실제 0이며, 데이터가 없는 값은 가능한 한 `null`로 구분하세요.

## 운영 시 확인할 사항

1. 새 Excel의 시트명이 기존 양식과 같은지 확인합니다.
2. 영업소 코드가 기존 8개 코드와 같은지 확인합니다.
3. DRUM과 EA를 합산하지 말고 각각 확인합니다.
4. 월간 매출이익과 영업이익의 부호를 확인합니다.
5. `유종 미분류`가 남아 있으면 유종 매핑을 완료합니다.
6. GitHub에 올린 뒤 강력 새로고침하여 새 `data.json`이 반영됐는지 확인합니다.

## 비밀번호 변경

현재 비밀번호는 브라우저에서 SHA-256 해시로 비교합니다. `script.js`의 `PASSWORD_HASH`를 새 비밀번호의 SHA-256 값으로 바꾸면 됩니다.

정적 GitHub Pages의 비밀번호 화면은 **간편 접근 제한**이며 서버 인증이 아닙니다. 민감한 원본이나 개인정보를 저장소에 올리지 마세요. 강한 보안이 필요하면 비공개 서버 인증, 사내 VPN, 또는 권한 관리가 있는 호스팅을 사용해야 합니다.
