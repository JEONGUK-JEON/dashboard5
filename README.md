# BWC 영업 대시보드

BWC 영업본부의 주간·월간 실적을 분리해 보는 정적 웹 대시보드입니다. 별도 서버나 데이터베이스 없이 GitHub Pages에 올릴 수 있습니다.

## 핵심 구성

- 로그인 비밀번호: `bwc1561`
- 주간보고: DRUM 수량, DM 전년 동기비, 매출, 계획 달성률, 매출 전년 동기비, 누계 매출
- 월간보고: 주간과 동일한 DRUM 수량, DM 전년 동기비, 매출, 계획 달성률, 매출 전년 동기비, 누계 매출 + 영업이익, 영업이익률
- 조직 필터: 동부·중부·서부 본부 → 부산·울산·포항·광주·천안·충주·수원·인천 영업소
- 유종별 영업이익률: 별도의 `유종별 이익분석.xlsx`를 영업소·유종별로 자동 집계
- 월간 미수: 월간 파일의 `영업소_미수` 시트를 읽어 영업소별 총 미수·당월 미수·2개월 이하·3개월 이상을 비교

현재 예시 데이터에는 월간 파일에서 읽은 2026년 1~7월 미수 자료와 `8월 유종별 이익분석.xlsx`에서 읽은 2026년 8월 유종별 자료가 포함되어 있습니다. 월간 기준월과 유종별 기준월이 같은 경우 월간 화면에 함께 표시됩니다.

## 파일 구성

```text
index.html   화면 구조와 로그인/업데이트 창
styles.css   화면 디자인과 반응형 레이아웃
script.js    필터, 집계, 차트, Excel 변환 로직
data.json    대시보드 데이터
README.md    설치와 업데이트 안내
```

## GitHub Pages에 올리기

1. 위 5개 파일을 GitHub 저장소의 같은 폴더에 올립니다.
2. 저장소의 **Settings → Pages**로 이동합니다.
3. **Deploy from a branch**를 선택하고, 배포할 브랜치와 `/ (root)`를 지정합니다.
4. 안내된 GitHub Pages 주소로 접속합니다.
5. 비밀번호 `bwc1561`을 입력합니다.

`data.json`을 읽기 위해 웹 서버가 필요합니다. 컴퓨터에서 `index.html`을 직접 더블클릭하면 브라우저 보안 정책 때문에 데이터가 표시되지 않을 수 있습니다.

로컬 확인 예시:

```bash
python -m http.server 8000
```

그다음 브라우저에서 `http://localhost:8000`을 엽니다.

## 가장 쉬운 데이터 업데이트 방법

대시보드 오른쪽 위의 **Excel 업데이트** 버튼을 사용합니다.

1. 주간 갱신 시 `※ 작성방법_주 마감.xlsx` 형식의 파일을 **주간보고 Excel**에 선택합니다.
2. 월간 갱신 시 `※ 작성방법_마감자료.xlsx` 형식의 파일을 **월간보고 Excel**에 선택합니다. 이 파일에서 월별 실적과 미수 자료를 함께 읽습니다.
3. 유종별 갱신 시 `8월 유종별 이익분석.xlsx`처럼 파일명에 기준월이 들어간 파일을 **유종별 이익분석 Excel**에 선택합니다.
4. **변환 및 미리보기**를 누릅니다.
5. 화면의 수치와 영업소 구성을 확인합니다.
6. **data.json 다운로드**를 누릅니다.
7. GitHub 저장소의 기존 `data.json`만 내려받은 파일로 교체합니다.

세 파일은 한꺼번에 올려도 되고 필요한 파일 하나만 올려도 됩니다. 선택하지 않은 자료는 기존 값이 유지됩니다. 새 파일을 변환해도 이전 주차·이전 월 데이터는 삭제되지 않고 기간별로 누적됩니다. 같은 기간을 다시 올리면 해당 기간만 새 값으로 교체됩니다.

월간 파일에서는 `2601`, `2602`처럼 `YYMM` 형식으로 된 시트를 모두 읽습니다. 실제 실적이 들어 있는 월만 기간 선택 목록에 추가되므로 1월부터 최신 월까지 계속 조회할 수 있습니다.

### Excel에서 읽는 시트

| 구분 | 시트 | 사용 항목 |
|---|---|---|
| 주간 | `주 마감` | 본부, 영업소, 코드, 포장단위, 계획/실적/전년 수량, 계획/실적/전년 매출, 누계 |
| 월간 | `YYMM` 시트(예: `2607`) | 본부, 영업소, 포장단위, 계획/실적/전년 수량, 계획/실적/전년 매출, 누계, 영업이익 |
| 월간 보조 | `거래형태별 이익` | `YYMM` 시트가 없을 때 본부, 영업소, 포장단위, 실적수량, 실적금액, 영업이익을 읽는 예비 자료 |
| 월간 기간 판정 | `BWC` | 보조 자료의 마지막 실적 월 판정 |
| 월간 미수 | `영업소_미수` | 본부, 영업소, 소계, 당월 미수, 2개월 이하, 3개월 이상 |
| 유종별 | 첫 번째 시트 | 유종대분류, 부서코드, 단위부서명, 포장단위, 실적수량, 실적금액, 실적영업이익 |

`미수현황`의 거래처별 상세 정보는 개인정보 노출을 줄이기 위해 읽지 않습니다. 월간 화면에는 `영업소_미수`의 영업소별 합계만 표시합니다.

## 유종별 파일 준비 방법

- 파일 형식은 `.xlsx`를 사용합니다.
- 파일명에 `8월`, `9월`처럼 기준월을 포함합니다. 연도까지 구분하려면 `2026년 8월 유종별 이익분석.xlsx`처럼 작성합니다.
- 첫 번째 시트의 기존 열 이름을 바꾸지 않습니다.
- 분석 기준은 `유종대분류`입니다. 이름 끝의 `(상)`은 상품 구분 표시로 보고 제거한 뒤 같은 대분류에 합산합니다. 예: `기타유제(상)` → `기타유제`.
- 영업소 코드는 `A1210`, `A1220`, `A1230`, `A1332`, `A1340`, `A1250`, `A1320`, `A1310`을 사용합니다.
- 영업이익률은 파일에서 읽지 않고 화면에서 `실적영업이익 ÷ 실적금액`으로 계산합니다.

유종별 자료는 월간 실적과 독립적으로 표시됩니다. 선택한 월의 유종별 자료가 없으면 가장 최근에 업로드한 유종별 자료를 표시하며, 표와 차트의 배지에 기준월을 표시합니다. 본부·영업소 버튼은 월간 실적과 유종별 자료에 동일하게 적용됩니다.

## data.json 구조

```json
{
  "meta": {},
  "organization": [],
  "weekly": [
    { "period": "2026-W34", "asOf": "2026-08-21", "records": [] }
  ],
  "monthly": [
    { "period": "2026-07", "records": [] }
  ],
  "monthlyTrend": [],
  "receivables": [
    { "period": "2026-07", "records": [] }
  ],
  "productProfit": [
    { "period": "2026-08", "records": [] }
  ]
}
```

### 주간 레코드 필수 필드

| 필드 | 의미 |
|---|---|
| `division`, `office`, `officeCode` | 본부, 영업소, 영업소 코드 |
| `packageUnit` | `DRUM` 또는 `EA` |
| `planQuantity`, `quantity`, `priorQuantity` | 주간 계획·실적·전년 수량 |
| `planRevenue`, `revenue`, `priorRevenue` | 주간 계획·실적·전년 매출(원) |
| `ytdPlanQuantity`, `ytdQuantity`, `ytdPriorQuantity` | 누계 수량 |
| `ytdPlanRevenue`, `ytdRevenue`, `ytdPriorRevenue` | 누계 매출(원) |

### 월간 레코드 필수 필드

| 필드 | 의미 |
|---|---|
| `division`, `office`, `officeCode` | 본부, 영업소, 영업소 코드 |
| `product` | 유종 또는 제품군 |
| `planQuantityDrum`, `planQuantityEa` | 단위별 계획수량 |
| `quantityDrum`, `quantityEa` | 단위별 실적수량 |
| `priorQuantityDrum`, `priorQuantityEa` | 단위별 전년수량 |
| `planRevenue`, `revenue`, `priorRevenue` | 계획·실적·전년 매출(원) |
| `ytdPlanRevenue`, `ytdRevenue`, `ytdPriorRevenue` | 누계 계획·실적·전년 매출(원) |
| `operatingProfit` | 영업이익(원) |

### 미수 및 유종별 보조 데이터

| 구분 | 주요 필드 |
|---|---|
| `receivables` | `division`, `office`, `officeCode`, `totalReceivable`, `currentReceivable`, `under3Months`, `over3Months` |
| `productProfit` | `division`, `office`, `officeCode`, `product`, `quantityDrum`, `quantityEa`, `revenue`, `operatingProfit` |

숫자는 쉼표나 `원` 문자가 없는 JSON 숫자로 저장합니다. `0`은 실제 0이며, 데이터가 없는 값은 가능한 한 `null`로 구분하세요.

## 운영 시 확인할 사항

1. 새 Excel의 시트명이 기존 양식과 같은지 확인합니다.
2. 영업소 코드가 기존 8개 코드와 같은지 확인합니다.
3. DRUM과 EA를 합산하지 말고 각각 확인합니다.
4. 월간 영업이익의 부호와 영업이익률을 확인합니다.
5. 월간 기준월과 유종별 파일명의 기준월이 같은지 확인합니다.
6. 미수 합계가 월간 원본의 `영업소_미수`와 일치하는지 확인합니다.
7. GitHub에 올린 뒤 강력 새로고침하여 새 `data.json`이 반영됐는지 확인합니다.

## 비밀번호 변경

현재 비밀번호는 브라우저에서 SHA-256 해시로 비교합니다. `script.js`의 `PASSWORD_HASH`를 새 비밀번호의 SHA-256 값으로 바꾸면 됩니다.

정적 GitHub Pages의 비밀번호 화면은 **간편 접근 제한**이며 서버 인증이 아닙니다. 민감한 원본이나 개인정보를 저장소에 올리지 마세요. 강한 보안이 필요하면 비공개 서버 인증, 사내 VPN, 또는 권한 관리가 있는 호스팅을 사용해야 합니다.
